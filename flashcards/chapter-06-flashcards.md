## Chapter 6: Product and Model Selection — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | When should you use Projects instead of Chat? | When work is ongoing and needs persistent shared context, a knowledge base, and custom instructions across multiple sessions. Exam tip: Chat = one-off; Projects = recurring, context-rich work. |
| 2 | What is Research mode designed for? | Multi-source exploratory questions requiring synthesis and citations across documents/web sources. Exam tip: pick Research mode when the scenario emphasizes 'gather and synthesize from multiple sources.' |
| 3 | What are Artifacts used for? | Generating standalone, reusable structured content (code, documents, reports) displayed in a separate pane, editable independently of the chat thread. Exam tip: 'standalone reusable output' = Artifacts. |
| 4 | Best use case for Haiku | Fast, low-cost model for simple, high-volume tasks like classification or short replies. Exam tip: scenario mentions 'thousands of tickets' or 'as cheap/fast as possible' → Haiku. |
| 5 | Best use case for Sonnet | Balanced default model for most everyday knowledge-work tasks (drafting, summarizing, coding, analysis). Exam tip: Sonnet is the default unless the scenario demands speed/cost (Haiku) or max reasoning (Opus). |
| 6 | Best use case for Opus | Highest-capability model for complex, multi-step reasoning and nuanced judgment where accuracy outweighs cost/speed. Exam tip: look for 'nuanced,' 'complex reasoning,' or 'accuracy matters most.' |
| 7 | How does context window size compare across Haiku, Sonnet, and Opus? | All three models share the same context window (~200K tokens) as of 2026. Exam tip: the models differ in capability/cost/speed, NOT context window size. |
| 8 | What should you do when a document exceeds the context window? | Chunk the document into smaller sections, or use a Project's knowledge base for retrieval instead of pasting the entire document at once. Exam tip: 'extremely long document' scenario = chunking, not a bigger model. |
| 9 | Key differentiator: Chat vs Projects | Chat is ephemeral and single-session; Projects persists a knowledge base and instructions across many conversations. Exam tip: 'repeated/ongoing work' signals Projects. |
| 10 | Cost/speed ranking of Claude models | Haiku (fastest, cheapest) < Sonnet (balanced) < Opus (slowest, costliest, most capable). Exam tip: match model tier to the stated priority — cost/speed vs. accuracy. |
| 11 | Common exam trap in model selection | Choosing Opus for simple high-volume tasks (wasteful/overkill) or Haiku for complex nuanced reasoning (underpowered). Exam tip: match task complexity to model capability precisely. |
| 12 | Artifacts vs. inline Chat response | Artifacts isolates generated content into a separate, reusable, editable object; Chat keeps content embedded only in conversational history. Exam tip: 'standalone' or 'reusable' keywords point to Artifacts. |
