## Chapter 8: Troubleshooting and Optimization — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three most common root causes of a weak or generic Claude output? | Missing context, ambiguous instructions, wrong/unspecified format request. Exam tip: diagnose which of these three applies before assuming the model lacks capability. |
| 2 | What's the core diagnostic question when troubleshooting a weak output? | Ask: 'What did I actually ask for vs. what did I actually want?' Exam tip: the gap between the literal request and the intended outcome is usually the real problem, not the model. |
| 3 | Claude asks a clarifying question instead of answering your prompt. What should you do? | Treat it as a diagnostic signal — it pinpoints exactly which part of your prompt was ambiguous. Update the prompt with that detail rather than resending it unchanged. |
| 4 | The same formatting complaint has come up across 5 separate chat sessions over two weeks. What's the correct fix? | Fix it at the custom instructions or knowledge source level, not with another one-off prompt edit. A problem recurring across sessions signals a systemic fix is needed. |
| 5 | A deployed workflow still produces correct output but takes 12 manual steps, including 3 redundant reformatting prompts. What should you do? | Optimize: trim redundant steps and tighten the format request in the original prompt. 'It works' is not the same as 'it's optimized.' |
| 6 | Custom instructions vs. editing a single prompt — when do you use each? | Use custom instructions for a recurring preference (tone, format, structure) that should apply across ALL future chats. Use a one-off prompt edit only for a single, unique request. |
| 7 | You need Claude to reference the same style guide across dozens of unrelated chats without retyping it. Best solution? | Add it to a Project's knowledge base. Exam tip: knowledge sources persist across sessions; pasting into chat each time does not. |
| 8 | A user needs Claude to read/write files and run terminal commands but is stuck in the Claude.ai chat interface. What's the fix? | Switch surfaces — use Claude Code (or the API with tool use), not more prompt tweaking. Exam tip: recognize when the limitation is the surface/model choice, not the prompt. |
| 9 | When should you suspect the MODEL or SURFACE is the problem, not the prompt? | When the task requires a capability the current surface doesn't support (e.g., file access, tool use, required context length) — no prompt rewrite fixes a true capability gap. |
| 10 | Standard context window size for current Claude models? | 200K tokens. Exam tip: if a workflow repeatedly loses earlier details or truncates, check document/conversation length against this limit before blaming the prompt wording. |
| 11 | How many examples are typically enough to fix recurring format drift via few-shot prompting? | 2–3 well-chosen examples are usually sufficient. Exam tip: few-shot examples are a lightweight fix for 'wrong format request' as a root cause of weak output. |
| 12 | Exact instruction to eliminate unwanted preamble like 'Sure! Here's...' from every response? | 'Respond with only the requested content — no preamble, no restatement of the request.' Exam tip: place this in custom instructions if it's a recurring complaint, not a single prompt edit. |
